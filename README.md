# 電車チェック

「今から15分後（駅までの徒歩時間）以降に出る電車」を、Alexaに聞くと答えてくれて、Androidのホーム画面（ウィジェット）とWebアプリでも同じ情報を見られるセットです。時刻表は自分で入力する方式なので、API登録は不要で無料で使えます。

- 並びは**到着が早い順**です。後から出て先に着く電車（快速など）に追い抜かれる電車は表示しません
- Webアプリは**位置情報**を使って、今いる場所から出るルートだけを表示します
- ウィジェットは**1分ごとにルートを切り替え**ます（上の行をタップすると次のルートへ）

```
shared/          ← ここだけ編集する（core.js と timetable.json）
  core.js          次の電車を探すロジック（日本時間・平日/土曜/土休日・祝日・深夜0時台に対応）
  timetable.json   ルートと時刻表
docs/            ← Webアプリ（GitHub Pages でそのまま公開できる）
android/         ← Androidウィジェットアプリ（Java、追加ライブラリなし）
.github/workflows/android.yml   ← push するとAPKをビルド
alexa/           ← Alexaスキル（Alexa-hosted / Node.js）
  skill-package/interactionModels/custom/ja-JP.json   対話モデル
  lambda/index.js                                     スキル本体
sync.sh          shared/ のファイルを docs/・alexa/lambda/・android の assets にコピー
test/core.test.js            ロジックのテスト
test/crosscheck.js, test/java/   JS版とJava版（ウィジェット）の計算が一致するかの照合
```

## 1. 時刻表（shared/timetable.json）

南与野・赤羽・上野・日暮里・北千住の時刻を、JR東日本「駅の時刻表」（2026年10月版）の各列車の停車駅一覧から作成済みです。特急（ひたち・ときわ・あかぎ・草津四万など）は除いています。

| ルート | 経路 |
|---|---|
| 家 → 大学 | 南与野 →（埼京線）→ 赤羽 →（上野東京ライン／京浜東北線）→ 上野 or 日暮里 →（常磐線）→ 北千住 |
| 大学 → 家 | 北千住 →（常磐線）→ 上野 or 日暮里 →（京浜東北線／上野東京ライン）→ 赤羽 →（埼京線）→ 南与野 |
| 家 → バイト先 | 南与野 →（埼京線）→ 赤羽 →（上野東京ライン／京浜東北線）→ 上野 |
| バイト先 → 家 | 上野 →（上野東京ライン／京浜東北線）→ 赤羽 →（埼京線）→ 南与野 |

すべての組み合わせから、一番早く着く行き方を自動で選びます。後から出て先に着く行き方があるときは、追い抜かれる方は表示しません。

自分の環境に合わせて変えるとよい値：

| 項目 | 今の値 | 意味 |
|---|---|---|
| `routes[].walkMinutes` | 家15分・大学10分・バイト先5分 | 出発地から駅までの徒歩分数 |
| `transferMinutes` | 赤羽4分・上野6分・日暮里4分 | 乗り換えにかける分数。これより短い乗り換えは使わない |
| `places` | 南与野駅・北千住駅・上野駅の位置 | 家・大学・バイト先の緯度経度。Googleマップで地点を長押しすると出る |
| `placeRadiusMeters` | 1500 | この距離以内なら「その場所にいる」とみなす |
| `webAppUrl` | 空 | 公開したWebアプリのURL（ウィジェットのタップ先と時刻表の自動取得に使う） |
| `widgetRoutes` | 4ルート | ウィジェットで順番に表示するルート |

`segments` が区間ごとの時刻表で、1便が `"発-着 種別"`（0時台は `24:xx`）です。平日（`weekday`）と土休日（`holiday`）があり、土曜は土休日ダイヤを使います。

値を変えたら次を実行します。

```sh
./sync.sh
node test/core.test.js
```

ダイヤ改正（毎年3月ごろ）のあとは時刻表を作り直す必要があります。`data/` に、取得したデータ（`enc*.txt`）と、それから timetable.json を作るスクリプト（`build_timetable.py`）が入っています。

## 2. Webアプリ

1. GitHub にリポジトリを作って全体を push する
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` と `/docs` にする
3. 表示された URL を Android の Chrome で開き、メニューから「ホーム画面に追加」（または「アプリをインストール」）を選ぶ
4. アイコンを長押しすると、4ルートに直接飛ぶショートカットが出る

- 無料の GitHub Pages ではリポジトリが公開になるので、最寄り駅を人に見られたくない場合は `docs/` フォルダを [Netlify Drop](https://app.netlify.com/drop) にドラッグする方法もあります（URLを知っている人しか見られません）
- アプリの「駅まで徒歩 −/＋」で変えた分数はスマホの中だけに保存され、Alexa とウィジェットには反映されません
- `places` を入れると、開いたときに位置情報の許可を聞かれます。家の近くなら「家→大学」「家→バイト先」だけ、大学の近くなら「大学→家」だけを表示します。「すべて表示」で全ルートに戻せます。ホーム画面のショートカットから開いたときは、そのルートを表示します
- 一度開けばオフラインでも動きます

## 3. Androidウィジェット

ホーム画面に置くと、次のように表示されます。

```
家 → 大学                        1/4 ›
┌───────────────────────────────┐
│ 家を出るまで 05:37            │   ← 秒単位でカウントダウン
└───────────────────────────────┘
7:51発 [上野東京ライン]     8:46着
8:08発 [京浜→日暮里]        8:59着
8:15発 [上野東京ライン]     9:17着
平日ダイヤ ・ 到着が早い順 ・ 7:30
```

- 1分ごとに `widgetRoutes` の順でルートが切り替わる。上の行をタップするとすぐ次のルートへ
- 下の部分をタップするとWebアプリでそのルートを開く（`webAppUrl` が無いときは設定画面）
- 画面オフ中は更新が止まり、画面がつくとすぐ更新される（電池はほぼ使わない）

### APKを作る（GitHub Actions）

1. このフォルダ全体を GitHub に push する（Webアプリと同じリポジトリでOK）
2. リポジトリの「Actions」タブ →「Android APK」の最新の実行 → 下の Artifacts から `train-check-apk` をダウンロード（zipの中に `app-debug.apk`）
   - 手動で動かすときは「Run workflow」
3. APK をスマホに送って開く。「提供元不明のアプリ」の許可を求められたら、開くのに使ったアプリ（Chrome や ファイル）に許可する
4. アプリ「電車チェック」を開き、WebアプリのURLを入れて「保存して時刻表を取得」を押す →「ホーム画面にウィジェットを追加」

時刻表を GitHub で更新すると、ウィジェットは6時間以内に自動で取り直します（すぐ反映したいときはアプリで「保存して時刻表を取得」）。Android Studio がある場合は `android/` を開いてそのままビルドすることもできます。

## 4. Alexaスキル

1. https://developer.amazon.com/alexa/console/ask で、**Echoと同じAmazonアカウント**でスキルを作成する
   - 名前：電車チェック／ロケール：日本語／モデル：カスタム／ホスティング：**Alexa-hosted (Node.js)**／テンプレート：最初から作成
2. 「ビルド」タブ → 対話モデル → JSONエディター に `alexa/skill-package/interactionModels/custom/ja-JP.json` を貼って「モデルを保存」→「モデルをビルド」
3. 「コードエディタ」タブで `lambda/` の中身を置き換える
   - `index.js` と `package.json` は上書き、`core.js` と `timetable.json` は新規ファイルとして追加
   - 「保存」→「デプロイ」
4. 「テスト」タブで「開発中」を選び、`電車チェックで大学は何分` と入力して動作を確認する

開発中のスキルは、同じアカウントの Echo ですぐ使えます（審査は不要です）。

話しかけ方：

- 「アレクサ、電車チェックで大学は何分？」→ 家→大学
- 「アレクサ、電車チェックでバイト何分？」→ 家→バイト先
- 「アレクサ、電車チェックを開いて」→ 両方

Alexaも「到着が早い順」の1本目と2本目を答えます。例：「大学方面、次は南与野7時51分発です。赤羽で上野東京ライン、上野で常磐線に乗り換えて、北千住に8時46分に着きます。家を出るまであと6分です。その次は8時8分発、8時59分着です。」

### 「アレクサ、電車何分発？」だけで答えさせる

Alexaアプリの「その他」→「定型アクション」→「＋」から設定します。

- 実行条件：音声 →「電車何分発」
- アクション：カスタマイズ →「電車チェックを開いて」

同じように「大学何分」→「電車チェックで大学は何分」も作れます。

### 時刻表を1か所で管理する（任意）

`alexa/lambda/index.js` の `TIMETABLE_URL` に、公開した Webアプリの `timetable.json` の URL（例 `https://<user>.github.io/<repo>/timetable.json`）を入れてデプロイします。以降は GitHub の時刻表を更新するだけで Alexa にも反映されます（10分キャッシュ。取れなかったときは同梱の時刻表を使います）。
